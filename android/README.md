# ZaPassKa для Android

Клиент на Kotlin и Jetpack Compose. Работает с тем же хранилищем, что и
десктопная версия: формат описан в [docs/FORMAT.md](../docs/FORMAT.md), а
совместимость проверяется тестом против общих эталонных векторов.

Вход только по мастер-паролю. Телефон обычно вне корпоративной сети, до
контроллера домена не достучаться, поэтому хранилище на доменной учётке на
телефоне не откроется. Переведите его на мастер-пароль в разделе «Защита»
десктопного приложения.

## Защита на устройстве

**Вход по отпечатку.** Мастер-пароль нигде не сохраняется. Вместо этого ключ
хранилища запечатывается ключом из Android Keystore, который выдаётся только
после того, как устройство опознало владельца. Пароль остаётся единственным
способом вывести этот ключ с нуля, поэтому выключение отпечатка ничего не
теряет.

Включается кнопкой с отпечатком в шапке списка, когда хранилище открыто.
Добавление нового отпечатка на устройстве намеренно обесценивает ключ: тот,
кто его добавил, не должен получить доступ, и приложение вернётся к паролю.

**Запирание при сворачивании.** Когда приложение уходит с экрана, ключ
стирается из памяти. Возврат требует пароля или отпечатка. Единственное
исключение — переход в браузер за согласием Google, иначе подключение Диска
обрывалось бы на полпути.

**Скрытие в списке недавних.** Окно помечено как защищённое, поэтому в
переключателе приложений вместо содержимого пустая карточка.

> Побочный эффект: снимки экрана и запись экрана в приложении перестают
> работать, это одно и то же ограничение Android. Для менеджера паролей так и
> задумано, но если нужно снимать интерфейс, скажите, вынесу это в настройку.

Минимальная версия Android — 9.

## Сборка

```bash
cd android
gradle :app:testDebugUnitTest :app:assembleDebug
```

## Ключ подписи

Google привязывает OAuth-клиент типа Android к отпечатку сертификата, которым
подписан APK. Отладочный ключ у каждой машины свой, а на runner'е GitHub он
вообще создаётся заново при каждом запуске, поэтому для работы с Диском нужен
один постоянный ключ.

Создайте его один раз и храните надёжно: потеряете, и обновления придётся
ставить только со сносом приложения.

```bash
keytool -genkeypair -v -keystore zapasska.jks -alias zapasska \
        -keyalg RSA -keysize 4096 -validity 10000
```

Отпечаток, который нужно указать в Google Cloud:

```bash
keytool -list -v -keystore zapasska.jks -alias zapasska | grep SHA1
```

Значение для секрета репозитория:

```bash
base64 -w0 zapasska.jks          # macOS: base64 -i zapasska.jks | tr -d '\n'
```

## Включите Custom URI scheme у клиента

Google отключил этот способ возврата из браузера для новых Android-клиентов по
умолчанию. Пока он выключен, вход обрывается на экране согласия с текстом
«Доступ заблокирован: недопустимый запрос» и кодом `400: invalid_request`, а за
ссылкой «подробная информация об ошибке» скрывается
`Custom URI scheme is not enabled for your Android client`.

Лечится одним переключателем: в Google Cloud Console откройте Clients, затем
ваш Android-клиент, раздел **Advanced Settings**, и включите **Custom URI
scheme**. Изменение применяется за несколько минут.

Причина ограничения в том, что чужое приложение может зарегистрировать ту же
схему и перехватить ответ. У нас это закрыто двумя вещами: PKCE, из-за
которого перехваченный код бесполезен без проверочного секрета, и параметром
`state`, который сверяется при возврате. Долгосрочная альтернатива, которую
рекомендует Google, это Google Identity Services SDK, но он тянет за собой
Play Services, а приложение сейчас обходится без них.

## Секреты репозитория

| Секрет | Обязателен | Зачем |
|---|---|---|
| `ANDROID_GOOGLE_CLIENT_ID` | для работы с Диском | OAuth-клиент типа Android, package `com.zapasska` |
| `ANDROID_KEYSTORE_BASE64` | для подписанной сборки | содержимое `zapasska.jks` в base64 |
| `ANDROID_KEYSTORE_PASSWORD` | вместе с предыдущим | пароль хранилища ключей |
| `ANDROID_KEY_ALIAS` | вместе с предыдущим | псевдоним ключа, в примере `zapasska` |
| `ANDROID_KEY_PASSWORD` | вместе с предыдущим | пароль ключа |

Без секретов подписи собирается отладочный APK, и Диск в нём работать не
будет: отпечаток не совпадёт с зарегистрированным.

Отпечаток собранного APK печатается в логе сборки, шагом
«Report the certificate the APK was signed with». По нему удобно сверяться с
тем, что указано в Google Cloud.
